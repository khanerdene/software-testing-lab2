# Программ хангамжийн чанарын баталгаа ба туршилт - Лаб 2

Хичээлийн 2-р лабаар вебсайтийн хэрэглэгчийн чанарын баталгааг хангахийн тулд k6-аар load test хийж, тоон үзүүлэлтэнд үнэлгээ хийн, хангах ёстой latency-н SLO-г тавьж сурав. 

k6-аар хэдэн хэрэглэгч зэрэг ашиглахийг (VU) тестед зааж өгөх боломжтой ба үүгээр ачаалалтай байдлийг дуурайж болно. Эхлээд зөвхөн 5 VU-тай 1 минутын тестийг (run-05vu_initial.txt) явуулан, p95 = 362.63мс утгыг олж авав. 

Үүний дараа 5, 30, 100 VU-тай гурван түвшнээр тест хийж, онолын мэдлэгтэй харьцуулав. Онолд хэрэглэгч нэмэгдэх тусам throughput ихэсэж, хурд удааширана гэсэн ба жинэхэнэ тестед throughput ихэссэн ч хурд бага хэмжээгээр ихэссэн үр дүн ажиглагдав. Энэ нь тест хоорондын хэлбэлзлийн хэмжээ олон хүмүүс туршилтын сайтыг нэгэн дор ашигласнаас хамаарж болзошгүй. 

Дараагийн алхамд тестийг автоматаар давах, унах боломжыг олгоход threshold утга хэрэгтэй болно. SLI утгыг анхны тестээр олдсон p95-н утгаар авч, SLO утгыг түүний 1.5 дахинаар хэмээн 360 * 1.5 = 560мс гэж үзэж, нэмэлтээр 1%-с доош POFAD утгатай байхийг тавив. 30 VU-тай тестийг явуулахад p95 370.86мс < 540мс, POFAD 0 < 1% үр дүнтэй давж, санаатайгаар чанга threshold утга (p95 < 100мс) тавихад алдаа гараагүй ч p95 370.6мс ≮ 100мс байсан учир тест унав.
